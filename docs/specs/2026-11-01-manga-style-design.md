# 漫畫語彙設計：對白框、格子、加重表現與團體彩蛋

2026-11-01。本文件延伸 `docs/specs/2026-11-01-reader-mvp-design.md`，只改漫畫模式的畫面層；兩者衝突之處，漫畫模式的版面與樣式以本文件為準，資料層、三層分離、素材與抓取規則維持 MVP 規格。

## 目的

MVP 做出來之後，使用者在手機上讀 173-1，和紙本漫畫對照後的感想是：風格太單一。全話只有一種對白框、格子都是長方形、加重語氣永遠是粗體加放射狀背景，而且拍點格旁邊留了一大塊空白。這份設計要讓同一話裡的對白框、格子、加重表現隨劇情變化，讀起來像漫畫，同時保留遊戲的彩色背景、小人和團體色。

使用者已在樣稿上選定方向：**漫畫語彙全上、保留彩色**，黑白做成開關；團體特色只當彩蛋。

## 目標

1. 同一話裡的對白框依台詞性質換形狀，至少七種，吶喊框的尖刺每個都不一樣。
2. 格子有大小與疊放：新增兩格並排、大格疊小格，剪貼格改成傾斜紙片。
3. 加重表現依格子類型分工，集中線、速度線、閃光網點、色暈各司其職，不再每格都一樣。
4. 版面兩側留邊、斜切保留但接縫等寬、拍點格不再留空白。
5. 閱讀設定裡有黑白開關，只對背景與小人套灰階。
6. 依活動所屬團體自動套一層小彩蛋：字幕尾端的團體色、重要格角落的小圖案、對白框線條的一點個性。
7. 173-1 的分鏡用新的格子類型重做；「每句台詞剛好出現一次」的測試繼續成立。

## 非目標

- 不做整面網點，也不做「黑白網點漫畫」風格；黑白只是灰階開關。
- 不改對話模式。
- 不做其他話數、不做 Spine、不做 AI 導演的 API 批次。這些仍在 MVP 規格的「之後」。
- 團體特色不做設定頁、不做每個團體獨立的版面或字體。
- 不引入對白框、特效或漫畫版面的第三方函式庫；不用 canvas。

## 反目標（做出來也算失敗）

- 手機上卡頓：不用會動的 SVG 濾鏡（`feTurbulence`、`feDisplacementMap` 的動畫），不用 `filter: contrast` 做整面網點，不在每格疊多層 `blur`。目前每格一層背景模糊是上限。
- 整面蓋住畫面的網點。使用者看過，明確說煩。網點只能出現在局部：拍點格的空側、吶喊與揭曉格的閃光邊緣、手機訊息框的底色。
- 大片空白。任何一列格子，左右空出的寬度不得超過該列的三分之一；拍點格一律滿版。
- 對白框的文字進分鏡 JSON。分鏡仍只含編號與構圖指令；對白框形狀只能以列舉值指定。
- 自架完整繁中字體。字體只從 Google Fonts 載入。

## 已決定的事

### 版面

- **留邊**：所有寬度下，漫畫欄位兩側各留 10 px 紙色；寬度 ≥ 672 px 時仍置中、最寬 640 px。MVP 的「貼齊螢幕左右邊緣」取消。
- **斜切保留，接縫等寬**：相鄰兩格之間的紙色縫隙寬度固定，不管那條接縫是斜的還是平的；上格的底邊與下格的頂邊永遠平行。目前程式的斜切接縫約 26 px、平接縫約 4 px，這就是使用者要改的地方。斜切的方向仍由分鏡的 `edge` 決定；`est` 無框滿版，`trans` 平接，規則不變。接縫寬度由建置者定，建議 10 px。
- **拍點格（`beat`）**：改成滿版矮格（最小高度約 110 px）、橫向排列：角色小人（92 px）靠說話者那一側，對白框在另一側，剩下的區域鋪局部網點。原本的三分之二寬、左右交錯取消。
- **新格子類型**：
  - `pair`：兩格並排，`l` 恰好兩句，可以是不同說話者的連續對話。每半格各有自己的角色與對白框，背景各取左右半邊的裁切。和現有的 `split` 的差別：`split` 是兩人同時的反應（對白置中、角色置中），`pair` 是一來一往的對話。
  - `inset`：大格右下疊一個小格（寬約 46%，有硬陰影）。`l` 二到四句：最後一句放進小格，連同它的說話者；其餘放大格。小格的背景是同一張背景放大兩倍、模糊。
  - `insert` 改款：傾斜約 -2° 的白紙片，黑邊、硬陰影，底下的背景模糊並蓋一層白霧。小字維持「{who} 唸出的內容」。
- **`close`**：維持左圖右文，但背景改為角色代表色的柔和色暈（置於背景層之上、小人之下），`fx: blush` 的「///」照舊。

### 對白框

七種形狀。預設由規則從台詞判斷，分鏡可以覆寫。

| 形狀 | 什麼時候用 |
| --- | --- |
| `round` | 一般台詞。圓角框、尾巴指向說話者那一側。 |
| `shout` | 吶喊。尖刺多邊形，尖刺數依框的大小，每個尖刺的長度與角度帶少量隨機抖動，亂數種子是該句的 `r`，同一句每次渲染都長一樣。 |
| `cloud` | 心聲。沿著橢圓排一圈圓形組成雲朵，下方兩個越來越小的圓當尾巴。文字用圓體。 |
| `whisper` | 低聲、遲疑。虛線邊框，文字稍淡。 |
| `wobble` | 顫抖、驚嚇。外框是沿著矩形邊緣加抖動的折線。 |
| `cut` | 被打斷。右邊緣鋸齒、無尾巴（對應分鏡的 `cut`）。 |
| `phone` | 手機訊息。小圓角方框、淺灰底、右上角一個小訊號方塊。 |
| `box` | 旁白。直角方框、無尾巴、楷體。 |

規則的優先順序（第一個命中的生效）：

1. 說話者為空 → `box`
2. `phone` 為真 → `phone`
3. 整句被（）包住 → `cloud`
4. 這句在分鏡的 `cut` 裡 → `cut`
5. 格子類型是 `shout`、`impact`，或 `pop` → `shout`
6. `shake` 為真，或表情名含 surprise／cry／shock → `wobble`
7. 句尾是「……」或「…」且全句 ≤ 12 字，或表情名含 sad／down／shy／trouble → `whisper`
8. 其餘 → `round`

尾巴方向：和現在的 `speakerSide` 一樣，依場景內出現順序左右交替；`impact`、`split`、`reveal`、`shout` 的框置中，尾巴朝下中央或不畫。特寫格的尾巴固定朝左（小人在左）。

分鏡覆寫：每格可選填 `shape`，是和 `l` 等長的陣列，值是上表的八個名字之一；驗證層檢查長度與列舉值。沒有 `shape` 的格子走規則。

畫法：clip-path 會把邊框和陰影切掉，所以框的外形用一個 SVG 畫在文字後面（填白、黑描邊 2.5 px），文字本身是普通 DOM，框的尺寸依文字版面量出來。字級用 Aa 調整或視窗改變寬度時，框要跟著重畫。

### 加重表現（依格子類型分工）

| 格子 | 背景處理 | 加重 |
| --- | --- | --- |
| `est` | 無框滿版，不模糊 | 場景字幕（尾端帶團體色）、狀聲字在右上 |
| `talk`、`pair`、`inset` | 依 `cam` 取景 | 無；`tone: serious` 時上方暗角 |
| `close` | 放大模糊 + 角色色暈 | 框依規則多半是 `wobble` 或 `whisper`；`fx` 照舊 |
| `pop` | 放大、微模糊 | 速度線：從右側往左的水平細線，左側漸隱；框是 `shout` |
| `beat` | 微模糊 | 空側局部網點 |
| `insert` | 模糊 + 白霧 | 傾斜紙片 |
| `impact` | 背景壓暗到約 35% 亮度 | 白色集中線（中心留空）、超大 `shout` 框、雙描邊（外白內黑）、狀聲字在左上 |
| `reveal` | 背景調淡 | 大字照舊；邊緣閃光網點（中心留空） |
| `shout` | 微模糊 | 閃光網點 + `shout` 框 + 出場角色一排 |
| `mono` | 模糊 + 白霧 | `cloud` 框、圓體 |
| `split` | 左右各半 | 框依規則，兩半可以不同形狀 |
| `sfx` | 依 `cam` | 狀聲字大字在左上，黑字白邊 |
| `trans` | 黑底字幕 | 無 |

集中線和速度線用 CSS 漸層加遮罩，不用圖片。閃光網點是 radial-gradient 點陣加橢圓遮罩，只出現在格子邊緣。

**狀聲字**：Noto Sans TC 900，白字、2.5 px 黑描邊、右下 3 px 硬陰影，傾斜 -6° 到 -14°；`sfx` 格與鐘聲類用反相（黑字白描邊）。位置依格子類型固定，不由分鏡指定。

### 字體

全部來自 Google Fonts：Noto Sans TC 400／500（台詞）、Noto Sans TC 900（狀聲字、吶喊）、Huninn 粉圓（心聲）、LXGW WenKai TC（字幕、旁白、剪貼格，沿用）。

### 黑白模式

- 閱讀設定（Aa 面板）多一個「黑白」開關，只在漫畫模式顯示，預設關。
- 開啟時只對背景層與小人圖套 `grayscale(1)` 加少許對比。其他東西一律維持原色：特寫的角色色暈、`pop` 的色調、配角圓圈、害羞的「///」、閃亮記號、對白框、網點、狀聲字、團體色點綴。這就是使用者在樣稿上看過並接受的版本（2026-11-01 確認）。
- 偏好設定鍵 `bw`，和 `mode`、`size` 一樣記在 localStorage。

### 團體彩蛋

依這期活動在目錄裡的 `unit` 自動套，沒有任何設定介面。

- 團體色取目錄現有的 `UNITS` 表。
- **字幕**：場景字幕黑底的右端約 18% 換成團體色。
- **角落圖案**：`est`、`shout`、`impact` 格的角落放一個白色黑邊的小符號：Leo/need ✦、MORE MORE JUMP! ♡、Vivid BAD SQUAD ▲、Wonderlands×Showtime ★、25時 ☾。
- **對白框個性**，每團一項小差異：Vivid BAD SQUAD 的 `round` 圓角縮小（約 6 px）顯得有稜角；25時 的心聲預設用 `whisper` 的淡字；其餘三團維持預設。
- 混合活動（`none`）與 VIRTUAL SINGER：不套任何點綴。

### 分鏡格式變更

- `t` 新增 `pair`、`inset`。驗證：`pair` 的 `l` 恰好 2 句；`inset` 的 `l` 2–4 句；`split` 仍最多 2 句。
- 每格選填 `shape: BubbleShape[]`，長度須等於 `l`。
- 提示詞升到 `v3-manga`：說明新格子、`shape` 覆寫、以及「同一場景連續幾格要換格子形狀，不要連續三格 `talk`」。
- 173-1 的分鏡由開發者離線重做：用上 `pair`、`inset`、改款的 `insert`，拍點格照新版面，`promptVersion: "v3-manga"`。台詞編號的聯集規則不變。

### 檔案與資料

- 畫面層的改動集中在 `src/render/comic/`；對白框獨立成一個模組（形狀規則、SVG 畫法各一檔）。
- 團體彩蛋的對照表放在 `src/app/catalog.ts` 旁，渲染層只收「團體代號」。
- 樣稿在本機 `.superpowers/brainstorm/2356719-1793512603/content/`（`style-direction-v2.html` 是彩色版，`color-vs-bw.html` 是黑白對照），**不進 git**：裡面有遊戲台詞原文。建置者可以在本機參考它的 SVG 畫法與 CSS 數值。

### 建置者檢查後補充的決定（設計者的決定，不是使用者的）

- 對白框規則表和加重表現表若有出入，以對白框規則表為準。心聲有說話者時仍是 `cloud`。
- 背景縮圖缺檔時，格子退回**素紙色**，不再鋪整面網點（MVP 規格的「紙色加網點」改掉，因為整面網點是本文件的反目標）。對應的既有測試跟著改，「每句台詞剛好出現一次」的測試不動。
- `est` 無框滿版是「無框」而不是「出血」：它和其他格子一樣留在 10 px 留邊之內。
- 團體彩蛋的對照表放在 `src/app/`，渲染層透過選項收「團體代號」，渲染層自己不查目錄。
- 173-1 分鏡的重做屬於建置範圍，用本機的 `assets/public/episodes/event_173_01.json` 對照。

## 驗收

1. 手機寬度 390 px：兩側各 10 px 紙色；沒有橫向捲動；每條接縫在左右兩端量到的寬度相差 ≤ 1 px，斜接縫與平接縫同寬。
2. 173-1 全話：`pair`、`inset`、`insert`、`beat` 各至少一格；沒有任何一列左右空出超過三分之一寬；八種對白框中至少出現六種；吶喊框兩個以上且形狀不同。
3. `npm test` 通過：既有「每句台詞剛好出現一次」測試不變；新增對白框規則表、新格子類型與 `shape` 驗證的測試，用合成劇本與合成分鏡。
4. `npm run check:layout` 加上接縫等寬與空白比例的量測，全部通過。
5. 黑白開關：開啟後背景與小人變灰階、對白框與團體色不變；重新整理後保持。
6. 173 期（Leo/need）看得到字幕尾端的藍色與 ✦；用合成劇本模擬混合活動時沒有任何點綴。
7. 使用者在手機上翻完 173-1，確認「風格不再單一」且「網點不煩」。這是最後的驗收，前六項過了才做。

## 留給建置者決定

- 接縫等寬的實作方式（clip-path 的位移算法、或改用 SVG 遮罩），只要量得出來符合驗收 1。
- 對白框 SVG 的重畫時機（ResizeObserver、或在字級改變時重渲染整頁）。
- 速度線、集中線、閃光的實際漸層數值與遮罩範圍；樣稿的數值可以直接用。
- `inset` 小格在只有兩句時的角色安排。
- 角落圖案的大小與位置。
- 黑白模式的對比值。
